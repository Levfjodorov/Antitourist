# AntiTourist для Android · 0.1.1

Это исходный проект со сценарием сборки, а не готовый APK.
В текущей среде нет Flutter/Android SDK, загрузка SDK недоступна.
Flutter analyze, Flutter test, Gradle и запуск на телефоне здесь не выполнялись.
Сценарий запускает анализ и тесты до сборки и прекращает работу при ошибке.

## Что добавлено

- Русский интерфейс без аккаунта.
- Демо-подборка из локального JSON, карточки мест, интересы и фильтр необычности.
- Карта OpenStreetMap с маркерами, доступная по отдельной кнопке; нужен интернет.
- Подключение к пользовательскому HTTPS API; приложение не запускает backend само.
- Скрипт сборки для Windows/Linux/macOS и ручной GitHub Actions workflow.

Все пять демо-точек вымышленные. Координаты, рейтинги и доступность не проверены.
Backend 0.1 тоже использует вымышленные точки. Это проверка интерфейса, не городской путеводитель.
Время определяет количество точек. Нет расчёта пути, GPS, пошаговой навигации или реальных POI.
Выбор транспорта передаётся API; демо-подборка от транспорта пока не зависит.
Алгоритм детерминированный: одинаковые настройки дают одинаковую подборку.

## Вариант 1: Windows

Потребуются интернет, Python 3, Flutter stable в PATH и Android SDK.

1. Установить [Flutter](https://docs.flutter.dev/install) и выполнить
   [настройку Android](https://docs.flutter.dev/platform-integration/android/setup).
2. Установить Python 3 с [python.org](https://www.python.org/downloads/windows/), если его нет.
3. В терминале проверить `flutter doctor -v`. Исправить ошибки раздела Android toolchain.
   При необходимости выполнить `flutter doctor --android-licenses` и принять лицензии SDK.
4. Распаковать архив целиком. Открыть папку `antitourist` и запустить `Build-APK.cmd`.
5. После успешной сборки появится `dist/AntiTourist-0.1.1-test.apk`.

Либо из корня проекта:

```powershell
py -3 scripts/build_android.py
```

Для Linux/macOS: `python3 scripts/build_android.py`.
Скрипт генерирует Android-проект в `build/android-project`, копирует туда исходники,
добавляет разрешение INTERNET в основной manifest, запускает pub get, analyze, test
и `flutter build apk --release`. Основные мобильные исходники остаются в `mobile`.
Повторный запуск сохраняет сгенерированный Android-проект и локальный тестовый ключ.
Версия Flutter и pubspec.lock сохраняются рядом с APK для воспроизводимости.

Если Android toolchain требует другую Java, используйте JDK из актуальной Android Studio
и настройте его согласно `flutter doctor -v`; локальные настройки SDK в архив не входят.

## Вариант 2: GitHub Actions — без SDK на своём компьютере

Workflow подготовлен, но здесь не запускался. GitHub-аккаунт и доступный Actions runner нужны.

1. Создать репозиторий, желательно private.
2. Загрузить **содержимое** папки `antitourist` в корень репозитория, включая `.github/workflows/android-apk.yml`.
   Файл workflow должен оказаться прямо в `.github/workflows`, а не `antitourist/.github/workflows`.
3. Открыть Actions → Build Android APK → Run workflow.
4. При успешном запуске скачать artifact `AntiTourist-Android-test` внизу страницы запуска.
5. Распаковать artifact; внутри будет `AntiTourist-0.1.1-test.apk`.

Workflow выбирает текущий Flutter stable; версии зависимостей фиксируются после pub get.
Первый внешний запуск ещё может обнаружить ошибки совместимости или SDK: APK выдаётся
только после успешного анализа, тестов и сборки.

## Установка на телефон

Передать собранный APK на телефон и открыть его. Если Android попросит, разрешить
установку из этого источника. Для данного прототипа GPS-разрешения не нужны.
Подборка демо-точек работает без интернета; карта и режим API требуют интернет.

Это release-сборка, подписанная тестовым debug-ключом стандартного Flutter-шаблона.
Для публикации в Google Play нужны отдельный постоянный ключ и настройки выпуска.
Разные GitHub-запуски могут подписываться разными тестовыми ключами: если Android
отклоняет обновление, удалить предыдущую тестовую версию и установить новую.

## API

Отключить демо-режим и ввести адрес собственного HTTPS-сервера без query/fragment,
например `https://api.example.com`. Backend нужно разместить отдельно с корректным TLS.
Адрес `127.0.0.1` на телефоне указывает на телефон, не на компьютер.
Запрос: POST `/api/v1/routes/surprise`, старт фиксирован на центре Таллинна.
Мобильный клиент исключает точки с `legal_access != true`, но это флаг источника,
не доказательство проверенной доступности. Демо-точки никогда не объявляются проверенными.

Документация сборки: https://docs.flutter.dev/deployment/android
